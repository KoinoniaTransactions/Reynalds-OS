# Real Repository Execution Standard

## Status

Active governing standard.

## Rule

No work is complete unless it exists in the actual Reynalds OS repository files.

## Why This Exists

Earlier project planning created strong strategy and architecture, but some conversation-level approvals were not yet reflected in repository files. Reynalds OS must avoid conceptual completion claims.

## Required Completion Criteria

A change is complete only when:

1. The canonical repository files were inspected.
2. The correct file/object/module owner was identified.
3. The change was made in real files.
4. Documentation was updated.
5. Version and release notes were updated when meaningful.
6. A new release package was produced.

## Prohibited Claims

Do not say any of the following unless the repository proves it:

- "implemented"
- "locked"
- "production complete"
- "released"
- "updated in the OS"

## Accepted Language When Not Yet Implemented

Use:

- "approved strategy"
- "documented decision"
- "planned implementation"
- "pending repository implementation"
- "cannot verify from repository"

## Relationship To Chat

Chat may contain ideas, approvals, and explanations. Reynalds OS contains the project record.

If chat and repository conflict, the repository wins.
