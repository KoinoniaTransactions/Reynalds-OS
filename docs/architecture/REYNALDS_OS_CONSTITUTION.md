# Reynalds OS Project Constitution

This project is a production software platform with a multi-year roadmap.

Reynalds OS is a universal operating system for running businesses, organizations, ministries, projects, and personal operations from a single object-driven platform.

## Core Principle

Conversations are temporary. The repository is permanent.

Nothing important should exist only in a conversation. If a decision, direction, standard, or project state matters for future development, it belongs in the repository.

## Engineering Role

Future contributors, including AI assistants, should act as lead software architects.

Responsibilities include:

- Preserve architectural continuity.
- Review existing code before proposing major changes.
- Favor scalable, maintainable systems.
- Reuse before extending.
- Extend before creating new.
- Avoid isolated modules when integration with the Object Engine is appropriate.

## Architecture First

Before significant implementation:

1. Understand the existing architecture.
2. Inspect relevant code.
3. Identify reusable components.
4. Identify related data models.
5. Explain the proposed approach.
6. Wait for approval.

## Object-Driven Philosophy

Objects are the foundation of Reynalds OS.

Pages are views into objects.

New concepts should first be evaluated as potential objects before becoming standalone features.

## The Brain

The Brain is the orchestration layer of Reynalds OS.

It should understand objects, relationships, workflows, companies, people, timelines, automations, documents, finance, knowledge, and AI agents.

The Brain should strengthen the Object Engine, not bypass it.

## Documentation-First Development

Documentation is part of the product.

Every meaningful change should update project documentation before the work is considered complete.

At the end of significant development sessions, update:

- PROJECT_STATE.md
- SESSION_HANDOFF.md
- AI_CONTEXT.md
- ARCHITECTURAL_DECISION_RECORDS.md
- ROADMAP.md
- RELEASE_NOTES.md
- VERSION_HISTORY.md

## Decision Framework

When choosing between implementation options, prioritize:

1. Architectural consistency
2. Scalability
3. Reusability
4. Simplicity
5. Performance
6. Speed of implementation

## Long-Term Goal

Reynalds OS should become the single operating platform for every business, organization, ministry, project, and personal workflow managed by the user.

Every design decision should be evaluated against that long-term objective.
