# ROS-0040 — Koinonia ERP Screen Blueprint v1.0

## Mission

Define the primary screens Koinonia ERP needs so the system can move from architecture into usable interface design.

Core rule: Every screen must help the user know, decide, or act.

## Primary Screens

### 1. Home Dashboard
Daily command center for priorities, transactions, closings, draft requests, showings, tasks, risk, revenue, and recent activity.

### 2. CRM Screen
Relationship management for leads, agents, brokerages, referral partners, clients, contact history, follow-ups, and revenue history.

### 3. Transaction Screen
Single transaction workspace with overview, timeline, deadlines, documents, communication, QA, exceptions, financials, and activity log.

### 4. Contract Center
Drafting request management for new drafts, in-progress drafts, client waits, revisions, completed drafts, and version history.

### 5. Showing Center
Licensed showing coverage management for today's showings, requests, assignments, provider availability, feedback, and revenue.

### 6. Operations Work Queue
Prioritized work across new work, due today, waiting, QA required, ready to close, and overdue.

### 7. Finance Screen
Packages, invoices, payments, outstanding balances, revenue by service/client, and forecasted revenue.

### 8. Customer Success Screen
Review requests, testimonials, referrals, past-client follow-ups, relationship health, and anniversaries.

### 9. Knowledge Screen
SOPs, templates, Decision Playbooks, certified objects, engineering principles, and training materials.

### 10. Reports Screen
Sales pipeline, transaction volume, revenue, quality, capacity, marketing performance, customer success, and repository health.

### 11. Administration Screen
Users, roles, permissions, packages, pricing, templates, automations, and branding.

### 12. ROS Screen
Object Explorer, Change Log, Roadmap, Version History, Repository Health, Development Journal, and AI Command Center.
