# Koinonia Consultation Execution Toolkit

Status: Active Supporting System  
Date: 2026-08-14  
Business: Koinonia Transactions  
Department: Sales

## Purpose

This folder contains the operating tools used to execute, document, present, follow up, and train the Koinonia consultation process.

These documents do not create a separate sales methodology.

The canonical consultation method is governed by:

`BRAIN/KOINONIA_CONSULTATION_INTERVIEW_SYSTEM.md`

If a supporting document in this folder conflicts with the canonical Brain source, current service objects, approved pricing rules, brokerage/compliance requirements, or a newer controlling Koinonia rule, the controlling source governs and the supporting document must be updated.

## Toolkit

- `KOINONIA_CONSULTATION_FIELD_GUIDE.md` — live 20–30 minute conversation aid.
- `KOINONIA_CONSULTATION_SCORECARD.md` — live notes, diagnosis, commercial decision, outcome, and post-consultation record.
- `KOINONIA_POST_CONSULTATION_FOLLOW_UP_SYSTEM.md` — outcome-based email/text follow-up and cadence.
- `KOINONIA_CONSULTATION_PRESENTATION_SYSTEM.md` — modular presentation, leave-behind, pricing card, and brokerage scope-sheet logic.
- `KOINONIA_CONSULTATION_ROLE_PLAY_CERTIFICATION.md` — training scenarios, evaluation scorecard, objection drills, and consultation-readiness standard.

## Governing Operating Sequence

Field Guide → Scorecard → Diagnosis → Prescription → Decision → Follow-Up → First Engagement → Delivery Review → Earned Expansion.

## Non-Duplication Rule

Do not create alternate consultation scripts, alternate pricing language, or separate objection-handling methodologies in Marketing, Sales, presentation collateral, or training material.

Supporting assets should compress, operationalize, or train the canonical consultation system — never fork it.

## Pricing Rule

Before any live consultation, written proposal, or customer-facing pricing statement, verify the current approved pricing against the Koinonia Pricing Rules Catalog, applicable pricing/package objects, and current production website where applicable.

Do not treat a price copied into a field guide or training example as authority over the current pricing system.

## Portal / Technology Rule

Do not sell unfinished portal functionality, internal Reynalds OS systems, development-roadmap items, or internal technology as if they are current client-facing capabilities.

Technology supports the service. The service itself must solve the diagnosed problem.
